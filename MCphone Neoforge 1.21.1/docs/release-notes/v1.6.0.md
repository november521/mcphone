# MCphone v1.6.0

三件大的：**音乐播放的一堆毛病修干净了**、**唱片仓能直接从背包放唱片**、**接上了 NetMusic —— 网上的歌也能扛着走**。

**运行环境：** Minecraft 1.21.1 · NeoForge 21.1.200 或更高 · 客户端与服务端都需安装
**可选：** Curios —— 装了多一个手机槽
**可选：** Waystones（传送石碑）—— 装了多一个「传送石」App
**可选：** MCEF —— 装了多一个「浏览器」App
**可选：** NetMusic（网络音乐机）—— 装了唱片仓还收它刻的 CD
**可选：** Integrated Dynamics —— 装了**不**多任何东西，只让崩溃报告指认对人

**从 1.5.0 升级：** 直接替换 jar，**服务端也要换**（多了一个容器菜单、三个网络包、一个音效事件）。存档、好友关系、聊天记录、购买记录、App 安装状态、主屏图标位置、**手机里已经放着的唱片**全部原样保留 —— 唱片仓的存储格式一个字节都没动。

**有一处行为变了，你会立刻注意到**：曲库里不再列出游戏自带的唱片，往下看。

---

## 💿 曲库里的唱片没了 —— 这是修好，不是丢了

1.4.30 加原版唱片时，把它做成了曲库的一个「音源」：存档里所有唱片自动列进曲库。原版就有 19 张，装了模组的整合包里是几十上百张 —— **你自己放进 `config/mcphone/music/` 的那几首歌被埋在中间，翻都翻不到**。

现在曲库只有你自己的文件。唱片走它自己的入口：界面顶上那条**唱片仓**，放一张进去播的就是那一张。

这条同时也是「乱音」的根源。以前同一张唱片能**同时响两遍** —— 一遍走曲库（自己解码，只有你听得见），一遍走唱片仓（服务端播，周围人都听得见）。两份同样的音频错开一点点叠在一起，就是那个听起来很乱的声音。

## 🎧 音乐终于能好好放了

**放着放着停不下来** —— 修好了。旧代码把「音频通道停了」一律当成「这首放完了」，可一首**根本没出过声**的曲子也会立刻停，于是每 tick 换一首，一秒二十首地转下去，转不完。现在分清三种停法：真放完了才接下一首；一声没出算失败；缓冲喂不上就停下并在日志里说明，不再往下转。

**一个坏文件不该把游戏带走** —— 解码库遇到读不懂的文件时抛的是 `Error` 而不是 `Exception`，而 Minecraft 那一层只接得住后者。以前它会一路窜进游戏主循环。现在只停这一首。

**按停止反而重放** —— 唱片外放的界面以前不知道歌什么时候放完（服务端没有 tick 盯着它），那个键会一直停在「停止」的样子；点下去服务端一算根本没在放，就又从头放了一遍。现在下发的是「放到哪一刻为止」，界面自己算得出来。

## 🎵 MP3 放不出来时，它会告诉你为什么

打包的解码库**只认 MPEG-1**（采样率 44100 / 48000 / 32000 Hz，绝大多数音乐都是这一档）。MPEG-2 与 MPEG-2.5 —— 也就是低采样率的 MP3（22050 / 24000 / 16000 / 11025 / 12000 / 8000 Hz）—— 放不了。

以前碰上这种文件是**安静地没反应**：歌在列表里，点了没动静，日志里只有一行看不懂的数组越界。现在：

- 曲库里那一行**变灰**，鼠标停上去写着「MPEG-2 放不了，只认 MPEG-1」
- 日志里有完整规格，形如
  ```
  [MCphone] 打开 MP3 我的歌.mp3 —— MPEG-1 Layer III, 44100Hz, 立体声, 320kbps
  [MCphone] 放不了 local:老歌.mp3：MPEG-2 Layer III, 22050Hz, 单声道, 64kbps。
            这个播放器只认 MPEG-1（44100 / 48000 / 32000 Hz），请转成 44.1kHz 再放进来
  ```

**碰上了怎么办**：用任何转码工具转成 44.1kHz 的 MP3，或者干脆转成 OGG —— 那一档走游戏自带的解码器，最稳。

## 🎒 唱片仓：不用再关手机翻唱片了

以前放唱片只认主手，可手机界面里没有背包 —— 唱片收在背包深处时，你得**关手机 → 把唱片翻到手上 → 再开手机 → 点那一条**。

现在唱片仓那一行右边多了一个小键，点开是「唱片格 ＋ 你的背包」，直接把唱片拖进去，或者 shift 点击。关掉自动回到音乐 App，接着按播放就行。

主手那条路一个字没动：手上正好拿着唱片时，点那一条仍然一步放入。

## 🌐 装了 NetMusic 的话：网上的歌也能扛着走

用 NetMusic 的电脑方块搜歌、刻成 CD，**把 CD 塞进手机的唱片仓** —— 走到哪儿放到哪儿，周围人都听得见。

搜歌、登录、VIP、刻盘、歌词全是 NetMusic 的事，MCphone 只接手「放」这一件。没装它的话唱片仓照旧只收原版唱片，其余一切不变。

为什么网络音乐能外放而你硬盘上的 MP3 不能：服务端没法把你电脑里那个文件发给别人，但网上那首歌人人都拿得到 —— 它只需要广播一个地址，每个客户端自己去拉。

声音**跟着人走**，与原版唱片那一支一致。停止也停得准：原版的停止包按音效 ID 停，会把旁边放同一张唱片的人一起停掉；网络音乐这一支按人停，两个人同时放歌互不干扰。

## 🎨 音乐播放器的图标全齐了

上一首 / 播放 / 暂停 / 下一首 / 列表循环 / 单曲循环 / 随机 / 取出 / 从背包放 —— 九个键全部用上了贴图，不再有画字符兜底的。全都可以用资源包替换，路径见 README 的换肤那一节。

## 🔧 还有一些看不见的

- 靠右的那几个键不再贴着屏幕边放：它们的悬停高亮比键本身宽 3 像素，贴边时会一直铺到机身边框上
- 唱片仓那一行的提示语改短了 —— 原来那句 108 像素，而那一行只有 81 像素可用，一直在被截断
- 曲库表不再每帧重新拼一次。1000 首歌时，光是打开着音乐 App 站在那儿，以前每分钟要产生 40MB 垃圾
- 网络音乐的两处内部缺陷：快速「播放→停止」会漏下一个停不掉的声源；歌自然放完后客户端会一直攥着那个玩家的实体引用

## 给服主

这一版没有新增配置项。`serverconfig/mcphone-server.toml` 与 1.5.0 一致，只有 `allowFriendTeleport` 一项。

唱片仓的新界面是一个正经的容器菜单（物品搬运由原版裁决，服务端权威），与末影箱那个走同一套。

NetMusic 是**可选**的：没装它时，相关代码一行都不会执行 —— 判断「装没装」和「真去调它」分在两个方法里，客户端与服务端各一半。
