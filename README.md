# MCphone — Forge 1.20.1

> **分支说明**：这个仓库按 Minecraft 版本 / 加载器分分支。
> 你现在看的是 `1.20.1-forge`。能用的正式版在 [`main`](../../tree/main)（1.21.1 + NeoForge）。

**这一支还不能用。** 它现在是一副能编过、能装进游戏、能从创造栏里拿到手机物品的骨架，
手机的界面、App、网络层、联动一样都还没有。

## 现在有什么

- 一个能 `./gradlew build` 通过的 ForgeGradle 6 工程
- 手机物品：能合成（配方与 `main` 上那支完全一致）、能拿在手里、有中英文名与图标
- 创造模式物品栏

**右键手机没有任何反应**，这是刻意的——与其现在写一个半截的开机逻辑，
不如让它老实地什么都不做，移植时一眼看得出这里还没接。

## 怎么往下做

看 [`docs/PORTING.md`](docs/PORTING.md)。那份清单是对 `main` 分支上
**215 个文件、24,098 行**逐个扫出来的，不是凭印象列的：哪 111 个可以近乎照搬、
剩下 104 个各卡在哪一条 API 上、按什么顺序推进，都写在里面。

对照原实现时直接看 `main` 分支的同名文件。**移植时请连同那边的类注释一起搬**——
那些注释里记着的多半是"为什么不能那样写"，而那种知识在两个版本上通常一样成立。

## 环境

| | |
| --- | --- |
| Minecraft | 1.20.1 |
| Forge | 47.4.23 编译，运行时接受 `[47.4.0,)` |
| Java | **17** |
| Gradle | **8.8** |

后两条都与 `main` 分支不同，而且不能"统一"：

- **Java**：1.20.1 跑在 17 上（`main` 那支是 21）。用 21 编出来的 class 文件版本
  低版本客户端加载不了，而且报的错不会提到 Java 版本
- **Gradle**：ForgeGradle 6 不支持 Gradle 9（`main` 那支用的是 9.x），配置阶段就会炸

## 构建

```bash
./gradlew build          # jar 出在 build/libs/
./gradlew runClient      # 开发环境启客户端
```

第一次构建要下 Minecraft、下 MCP、反编译整个 Minecraft，本机实测 **33 分钟**
（瓶颈是网络不是 CPU），之后每次十几秒。CI 上只要 2 分钟。

## 发版

tag 写成 `forge-v<版本>`（例：`forge-v0.9.0`）。

带前缀是因为 **tag 在 git 里是仓库级的、不属于任何分支**，两个版本分支都用
`v1.0.0` 就撞了。至于该跑哪份 workflow 不用操心：推 tag 时 GitHub 用的是
**tag 所指向那个 commit 里的** workflow，打在这个分支上就跑这个分支的。

**在移植到"能用"之前不要发 release** —— 挂上去的包玩家会真的下载。
