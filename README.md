# MCphone — Forge 1.20.1

> **分支说明**：这个仓库按 Minecraft 版本 / 加载器分分支。
> 你现在看的是 `1.20.1-forge`。能用的正式版在 [`main`](../../tree/main)（1.21.1 + NeoForge）。

**移植已经做完，但还没有人在真游戏里点过。** 代码、专用服务端、
两道构建期校验都是绿的；界面这一层只在 `main` 分支上验过，这一支还没有。
在自己进游戏点一遍之前，别把它当成品用。

## 现在有什么

`main` 上那支的功能**全部就位**：

- 开机（右键手机 / 快捷键，手上、背包、饰品栏都能开）、主屏、状态栏
- 14 个 App：设置、应用商店、聊天、相机、相册、音乐、末影箱、记事本、
  传送石、浏览器、时钟、天气、阅读、任务书
- 网络层三十多个包、玩家数据、存档往返、服务端配置
- 七个联动：Curios、NetMusic、Patchouli、Waystones + Balm、MCEF、FTB Quests、GuideME

`main` 的 215 个源文件里搬了 213 个 —— 另外两个（`ModAttachments`、
`ModDataComponents`）被这一支的 `PhonePlayerData` 与 `PhoneItemData` 取代了。

## 还差什么

1. **进游戏逐个 App 点一遍**。这是唯一挡在 1.0.0 前面的一步：编译器管得了签名，
   管不了画得对不对
2. **配置界面**。那边挂的是 NeoForge 自带的 `ConfigurationScreen`，
   Forge 1.20.1 没有内置的，要自己写

## 移植是怎么做的

看 [`docs/PORTING.md`](docs/PORTING.md)。那份清单是对 `main` 分支上
**215 个文件、24,098 行**逐个扫出来的，不是凭印象列的：每一刀搬了什么、
哪条 API 在 1.20.1 上是另一套、哪些坑只在运行期才发作，都记在里面。

**改 bug 要改两遍**，两支不共用代码。但也别照着 `main` 的调用直接改这边 ——
联动那六个里有一半在 1.20.1 上是**另一套 API**，逐条写在 PORTING.md 的联动表里。

对照原实现时直接看 `main` 分支的同名文件。**移植时请连同那边的类注释一起搬**——
那些注释里记着的多半是"为什么不能那样写"，而那种知识在两个版本上通常一样成立。

## 环境

| | |
| --- | --- |
| Minecraft | 1.20.1 |
| Forge | 47.4.23 编译，运行时接受 `[47.4.0,)` |
| Java | **17** |
| Gradle | **8.8** |

后两条都与 `main` 分支不同，而且不能"统一"：

- **Java**：1.20.1 跑在 17 上（`main` 那支是 21）。用 21 编出来的 class 文件版本
  低版本客户端加载不了，而且报的错不会提到 Java 版本
- **Gradle**：ForgeGradle 6 不支持 Gradle 9（`main` 那支用的是 9.x），配置阶段就会炸

## 构建

```bash
./gradlew build          # jar 出在 build/libs/
./gradlew runClient      # 开发环境启客户端
```

第一次构建要下 Minecraft、下 MCP、反编译整个 Minecraft，本机实测 **33 分钟**
（瓶颈是网络不是 CPU），之后每次十几秒。CI 上只要 2 分钟。

## 发版

tag 写成 `forge-v<版本>`（例：`forge-v0.9.0`）。

带前缀是因为 **tag 在 git 里是仓库级的、不属于任何分支**，两个版本分支都用
`v1.0.0` 就撞了。至于该跑哪份 workflow 不用操心：推 tag 时 GitHub 用的是
**tag 所指向那个 commit 里的** workflow，打在这个分支上就跑这个分支的。

**在自己进游戏验过之前不要发 release** —— 挂上去的包玩家会真的下载，
而这一支的界面到现在为止没有任何人看过。
