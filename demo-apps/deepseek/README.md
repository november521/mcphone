# DeepSeek 轻量前端 App 0.1.0

使用现有 MCPhone 前端接口实现单次文本问答。独立 App id：`mcpapps:deepseek`，不修改本体，也不需要服务端安装附属。此客户端由 MCPhone 项目编写，使用通用聊天图标，并非 DeepSeek 官方 App。

## 安装和使用

1. 使用已验收的 PR #90 构建或包含其前端能力的后续构建，无需为本 App 更换 JAR。正式发布的 1.12.0 不包含所需的全部输入与请求取消能力。
2. 将 `deepseek.vue` 放入游戏目录 `mcphone/apps/`，重新进入 AppStore，从本地来源安装“DeepSeek”。
3. 打开 App → 设置，粘贴自己的 API Key 并保存，再点“返回问答”。Key 可从 [DeepSeek 开放平台](https://platform.deepseek.com/) 获取。保存仅写入本机，不会验证账户有效性；发送时才请求 API。
4. 输入问题后发送，等待纯文本回答；等待中可点“取消等待”。失败后可修改设置或问题并手动重试，不自动重复请求。

API Key 通过既有 `ctx.store` 保存在当前客户端账号、当前 App 的本地文件中，采用本体现有的明文存储机制。保存或离开设置会清空输入框，聊天页不显示 Key。请求时仅在固定官方地址的 Authorization 请求头中发送，不放进问题正文，也不发给 Minecraft 服务端。设置中的“删除密钥”可删除已保存值。

## 本版范围

- 单次独立问答，不附带上一轮问题或回答。关闭 App 不保存问题及回答，Key 可在重开后恢复。
- 固定调用 `https://api.deepseek.com/chat/completions`，模型 `deepseek-flash`，普通非思考模式、非流式；不包含图片、工具调用、多轮历史或 Markdown 渲染。
- 问题最多 1024 个 UTF-16 单元，Key 输入最多 256 个 ASCII 字符；请求最长等待 90 秒。输出设置 `max_tokens: 768`，显示最多 4096 个 UTF-16 单元，不拆开表情代理对。
- 达到模型长度上限或本地显示上限时有明确提示。网络接收仍使用本体 64 KiB 上限，异常响应不显示原始内容；401、402、429、5xx、超时、编码异常、空回答与 JSON 格式异常均恢复到可操作状态。
- “取消等待”只保证停止本地等待和后续结果处理，不保证远端停止生成或停止计费。

接口与错误规则对照 [官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/) 和 [官方错误码](https://api-docs.deepseek.com/quick_start/error_codes/)，核对日期 2026-11-02。

## 游戏验收

1. 不配置 Key 时不应发送请求。保存后聊天页可发送，关闭再打开应保留配置，但不恢复问题和回答。
2. 提问“用两句话解释红石比较器”，检查等待状态和实际回答；连续点击发送不应重复发起。
3. 再发一条较长问题，点击取消，随后旧回答不应覆盖界面；可以继续发送新问题。
4. 用无效 Key 检查密钥错误提示，再换回自己的有效 Key；不要把真实 Key 写入源码、测试记录或截图。
5. 测试密钥替换、未保存返回、删除及重开。手机和平板都检查设置、输入、发送、取消及回答滚动。

自动测试使用模拟 Key、确定性完成及本机回环 HTTP，不调用付费 API，也不把示例文字当成真实模型回复。有效 Key 的成功生成与游戏实际显示仍需由玩家验收。
