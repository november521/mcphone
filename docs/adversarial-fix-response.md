# MCPhone 对抗缺陷修复回执

工作分支：`step21-s15hi-thread-attribution`

## 已修复并有自动回归覆盖

- 唱片单曲循环：三平台接入服务端 tick，先判断旧轮次到期，再推进到稳定整轮边界；手机离身时停止并同步状态。
- 脚本沙箱：原生字符串/数组/JSON 高放大操作执行前预检，拒绝类数组 getter TOCTOU；宿主包装层纳入重入深度；驻留清扫不执行 getter 且仍在 Rhino Context 内。
- 并发与归因：`AppScope`、模块缓存/加载栈、`SharedState` 脏键交接串行化；包结构、类型与配额错误不再记为玩家 strike。
- RPC/幂等：落地异常统一收口并结算保留项；`check()` 恢复只读语义；键改为长度前缀编码，消除分隔符与 null/空串碰撞。
- 网络入口：三平台 C2S 非 VM 致命异常统一隔离；终端、壁纸、亮屏增加持机校验；购买、好友、笔记、设置类状态变更分组限流。
- 聊天：图片分片逐片复验权限与大小，图片请求去重并限制单次总回包；已读写入要求好友关系且持久状态限制为 100 个联系人。
- 数据与日志：DST 回拨边界稳定；日志清除全部 Unicode 格式/换行控制； provider 栈限制 256 帧；本地存储阻断点段和 Windows 设备名并向调用方返回保存结果；流水字段在 `TxnLog` 边界自校验。
- 壁纸：C2S 字符串限制 255 字符，只接受单个 `.png` 文件名，拒绝路径分隔符和控制字符。

## 需要产品方案后再改

- **ADV-09**：256 条/玩家容量是否调整，以及结果不明的 `RESERVED` 是否允许过期。当前已封住已知 authority 异常泄漏并保证 `check()` 无副作用，但不能擅自把“可能已发生资金效果”的保留项按时间删除。
- **ADV-22**：三条共享存储聚合配额的执行点。当前生产 `KvBackend` 尚未接线，应与后续持久化实现一起落地，避免在错误层重复计数。
- **G9**：聊天、笔记、商店、终端的服务端开关名称、默认值和迁移策略需产品经理确认。
- **§6 生产接线**：RPC pipeline、结果路由、SharedState 落盘、KV/sealed backend、货币注册与 local store 均属于尚未启用的后续功能，不能仅为消除静态告警而半接线。
- **AT-19**：`ScriptKv.with()` 当前在 64 键硬上限内为 O(n)；若产品提高配额或改成全服共享，再改增量字节计数。
