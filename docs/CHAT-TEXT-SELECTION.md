# 美西螈消息正文拖选

本次开发基于 `fe074d01007bdd7bd877a61e452cab8bfc4d40b9`，工作分支为 `codex/chat-text-selection`。

## 交互范围

- 在文字气泡内按住鼠标左键拖动，选择同一条消息中的部分文字；支持反向拖动与跨行。
- 松开左键后保留选区。拖出气泡仍归原消息；上下越界收敛到原文开头/末尾。
- `Ctrl+C`（macOS 使用原版对应复制快捷键）只复制已选原文。软换行不产生额外换行，原文空格和显式换行保留。
- 点击其他位置取消选区；点击输入框恢复输入焦点。选择消息期间输入框不接收字符或 Enter，草稿保留。
- 图片点击与附件菜单优先处理；图片查看器打开时仍拦截下层键盘、字符、拖动和松手。
- 当前不跨消息选择，不提供双击选词、右键菜单或拖至视口边缘自动滚动。

现有聊天发送链路会清洗掉显式换行；本次多行主要来自自动折行。选择组件本身保留原文显式换行，以兼容已有/未来消息数据，不改变发送校验和协议。

## 实现边界

`ChatTextLayout` 使用原版 `StringSplitter` 的位置回调获得原文区间，继续使用 `Font.split` 的视觉文字行绘制。各字形的浮点 advance、原文位置与 Java `\X` 字素边界组成不可变命中图，避免拆开代理对、组合重音、旗帜、肤色和 ZWJ emoji。即使原版在窄行中将一个字素折开，复制端点仍落在整个字素边界。

双向文本按视觉游程恢复原文位置，命中保留各游程方向。原版字形变换若改变字形数量、无法可靠映射，仍显示原文但不启用该消息拖选；没有把未知字形复制成错误的原文。

`ChatTextSelection` 保存稳定消息 ID、原文映射、起点、终点及拖动状态，不保存可变列表下标。追加消息及下标改变不串选区；历史重同步产生新对象时保留同 ID 的选区，消息淘汰、关闭/切换会话时清理。稳定 ID 随右键功能引入，见 [CHAT-MESSAGE-ACTIONS.md](CHAT-MESSAGE-ACTIONS.md)。

`ChatMessagePane` 负责消息几何、命中与高亮。绘制和命中共用 `textOrigin`，高亮使用细分坐标，按气泡→选区→文字顺序绘制，并沿用消息区裁剪。`ChatConversation` 负责复制快捷键和焦点协调，`PhoneScreen` 转发反缩放后的拖动与松手事件。`ChatComposer` 的 Enter 路径现在受输入焦点约束，发送按钮仍属于明确的发送操作。

这些类型在 `shared/` 客户端目录，不改变服务端数据、网络协议和附属 API，也不实现其他预留聊天功能。

## 自动化与实测

`ChatTextSelectionTest` 目前有 94 条断言，覆盖真实原版折行算法、局部/反向/跨行复制、变宽字符、重复子串、空行、越界、组合字符、真实双向排版、消息身份与淘汰。字体使用确定度量替身，不加载窗口/GL；不能据此宣称视觉与完整输入交互验收通过。

用户已反馈本地游戏测试无问题；以下清单用于后续回归，反馈未逐项列明测试覆盖范围。

游戏验收清单：

1. 中文“哎呀好想吃辣条”只选择“好想吃”，确认高亮贴合文字且没有移动原有正文。
2. 中英文、标点、空格和长消息跨行拖选；反向拖选；拖出上下左右边界后松手。
3. 复制到输入框/外部编辑器，确认内容与选择一致，自动折行不变成换行。
4. 不同手机缩放与 Minecraft GUI 缩放下，确认鼠标命中、高亮、裁剪一致。
5. 选中消息后滚动、收到新消息、达到 100 条缓存淘汰、切换会话，确认选区不串到另一条消息。
6. 输入框已有草稿时拖选消息：按字符或 Enter 不应修改/发送草稿；点击输入框后原版键盘选区、复制与 Enter 发送应正常。
7. 图片上传、图片点击/放大、查看器内 Enter/字符/滚轮、关闭查看器与附件菜单不应回归。
8. emoji/组合重音和资源包字体实测；自动化只验证索引与几何，不保证所有字体字形相同。

Windows 完整构建仍会在既有 `EconomyDataTest` 的 `Files.setPosixFilePermissions` 处失败；不删除、跳过或弱化该测试。最终平台构建结果、测试包 SHA256 与日志另附于本地实测包的验证记录。
