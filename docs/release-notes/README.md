# 发版说明怎么写

**一个小版本一份，不是一次发布一份。**

文件名按**基准号**走：`v1.10.2.md` 这一份被 `1.10.2-alpha.1`、`1.10.2-beta.1`、
`1.10.2-beta.2`、以及正式版 `1.10.2` **共用**。预发布期间就往那一份里写，转正时它已经
是完整的了。

## 平时怎么改

- **这条线已经切过预发布** → 直接改 `v<基准号>.md`（比如现在就是 `v1.10.2.md`）。
- **要开一条新线**（上一个正式版已经发出去了）→ 写 `next.md`。发版时它会被改名成
  `v<新基准号>.md`，之后就改那一份。

`next.md` 与 `v<基准号>.md` 同时存在时发版会停 —— 那种情况多半是有人在 `next.md` 里
又写了一遍已经写过的东西，得先并起来。

## 正式版发出去之后就别改了

那份说明此刻是一条**已经发生过的记录**：GitHub Release 页面、CurseForge、Modrinth 上
都是当时那个内容，仓库里再改只会让三处对不上，而且没人会发现。

`build.yml` 的 guard-version 会拦。判据是**正式版的 tag 在不在**：`v1.10.2-beta.2`
存在时那份还能改，`v1.10.2` 存在之后就不能了。

要补充说明就写进下一版。

## 为什么不按完整版本号命名

原先是那样，于是同一条线被切成 `v1.10.2-beta.1.md`、`v1.10.2-beta.2.md`、`v1.10.2.md`
三份，而最后那份是从新的 `next.md` 起的 —— **beta 阶段写进去的东西在正式版的说明里
全部丢掉**，前两份成了没人看的孤儿。

## 目录里那些 `forge-v*.md`

`1.20.1-forge` 还是独立分支时的存档，那条线自己发过几版。并进来之后不再产生新的，
留着是记录。
