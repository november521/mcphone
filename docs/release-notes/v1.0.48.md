# MCphone v1.0.48

手机里多了一个记事本，写完还能印成书带走 —— 以及一次要紧的服务端修复。

**运行环境：** Minecraft 1.21.1 · NeoForge 21.1.200 或更高 · 客户端与服务端都需安装
**可选：** Curios —— 装了多一个手机槽，不装一切照旧

---

## 🖥️ 专用服务器现在能正常启动了

**如果你在服务器上装过 MCphone 却起不来，这一版就是为你发的。**

旧版的手机物品类里写着一句打开界面的代码。那句代码被"只在客户端执行"挡得好好的，服务端永远跑不到它——但这不够。注册物品时服务端要加载这个类，JVM 校验它的时候就会去找界面相关的原版类，而专用服务器上根本没有那些类，于是当场崩溃。

**光是写着就会崩，不执行也一样。** 现在开界面的代码搬到了单独的客户端类里，服务端从头到尾不会碰它。

顺带说明：这个问题在单人游戏里完全不会出现，所以此前一直没被发现。

## 📝 记事本

主屏上的第八个 App。

- **笔记跟着人走**，不占手机物品的存储，换手机也还在。
- **死了不会丢**。日记本因为摔死一次就空了，那不是惩罚，是数据损坏。
- 列表页只拉摘要，点进去才拉全文 —— 笔记攒多了也不会卡。
- 单篇上限 2000 字，字数显示不会再和删除键打架。
- **删除要按两次**，第二次才真删。误触一下就没了的东西不该只问一次。

## 📖 写完可以印成一本书

在笔记里点"印成书"，就得到一本原版的**书与笔**，可以递给别人、放进箱子、挂在展示框上。

- 用原版的书，不自造新物品 —— 阅读、复制、署名、成书这些原版都做好了。
- **需要一本空白的书与笔**当纸。写过字的那本不会被当耗材烧掉。
- 分页按实际行数与页宽折行，一句话不会被劈在两页上；英文优先在空格处断，不会把单词劈成两半。
- 印完的提示显示在**手机屏幕里**，不用先关掉手机才看得见。

## 🔌 主动兼容其他模组

新增了一套兼容模块机制，专门用来绕开别的模组的问题 —— 而不是干等对方修。

首个使用者是 **Integrated Dynamics**。在大型整合包里，只要有任何一个模组注册失败，NeoForge 就会回滚整个注册表，而回滚过程会踩到 Integrated Dynamics 的方块掉落表，抛出一个空指针。

这个空指针本身不是崩溃的原因，**但它会把真正的原因盖住** —— 崩溃报告里只剩下一句看不懂的 `menril_torch_stone`，让人以为是 Integrated Dynamics 的锅。

现在 MCphone 会提前把它的掉落表定死，回滚时不再触发。**崩溃报告从此指认真凶。**（上面那条服务器修复，正是靠这个才被找出来的。）

装了 Integrated Dynamics 才生效，没装就完全不动。

## 🧩 给附属模组作者

这一版有**破坏性变更**。目前尚无已知的附属模组，所以选在这个时候一次改到位。

**API 按运行端重新分包**

```
com.november.mcphone.api.client.*   客户端专用（IPhoneApp、IAppSource）
com.november.mcphone.api.cost.*     两端安全（ICost）
```

界线写在包名里，一眼可见。`api.client` 下的实现类请放进你自己的客户端包，别让服务端代码引用到 —— 原因就是上面那条服务器修复，包注释里有完整解释和安全写法。

**App id 改成 ResourceLocation**

原来是裸字符串，两个模组各注册一个 `calculator`，后来的那个会被**静默丢弃**，作者还查不出原因。现在是 `yourmod:calculator`，撞名在结构上不可能发生。

老存档会自动迁移，玩家的安装/卸载选择不会丢。

**ICost —— 让操作有代价**

想让"下载你的 App"要求玩家先交点什么？实现 `ICost` 即可，也可以直接用现成的：

```java
ICost.of(Items.DIAMOND, 3)    // 三颗钻石
ICost.FREE                    // 白送
```

"印成书要一本空白书与笔"就是它的第一个使用者。这个接口两端安全，服务端代码可以放心引用。

**开发者指南重写了**

`IPhoneApp` 的文档里原来那段 Gradle 依赖是 ForgeGradle 写法，照抄会直接构建失败。现在给了正确的坐标、`neoforge.mods.toml` 的依赖声明，以及各处示例的修正。
