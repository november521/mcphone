# 原生管理与重启核对测试

以下操作由你在自己的测试客户端和测试服中执行。自动化目前覆盖配置事务、令牌、脚本开关及经济崩溃窗口，尚未替代原生页面的游戏内验收。

## 先准备管理身份

使用匹配平台的客户端与服务器。世界目录下 `serverconfig/mcphone-script-runtime.json` 的 `admin.deployment_approvers` 填入你的完整玩家 UUID，再由服务器控制台给予 OP 3 或以上权限。两个条件都满足才显示「服务器管理」。OP 单独不能修改配置或核对 UNKNOWN。

新配置的 `server_scripts` 默认为 `false`。旧配置缺少这一字段时同样关闭：需要你在原生页面预览并明确开启，或在配置中显式写 `true` 再由控制台运行 `/mcphone script runtimeReload`。关闭状态下，管理、已有收件箱领取和已有托管取消仍可用，服务端脚本及其后台任务不能运行。跨服信任首版保持关闭。

## 页面任务

| 编号 | 操作 | 应看到的结果 |
| --- | --- | --- |
| A1 权限交集 | 用普通玩家、仅 OP、仅在审批名单中的玩家、同时满足两者的玩家分别登录 | 只有最后一位能访问管理；伪造宿主请求也不能绕过服务器检查 |
| A2 撤权 | 打开预览，再从控制台撤掉 OP 或从配置移除 UUID 并重载；尝试确认 | 更改被拒绝，入口隐藏；旧预览不授予权力 |
| A3 三档完整差异 | 依次预览 hardcore、standard、open，逐页查看；先取消，再重新预览并确认 | 取消不改文件；确认采用 §31.2 的格数、KV、App 数、网络与边界。三档均关闭服务端脚本和跨服信任 |
| A4 预览过期与竞争 | 预览后等待两分钟；另一管理员修改同一配置；预览后断线重连 | 旧确认分别因过期、配置已改变、连接已改变而拒绝，必须重新预览 |
| A5 保留已有物品 | open 下存入/托管物品，再改 hardcore | 不能新增市场托管，已有物品和数据不被删除，原主仍可取消或取回 |
| A6 显式微调 | 切预设后单独调整一项能力、边界或配额；重启 | 微调继续生效，加载配置不会重新套预设覆盖你的显式值 |
| A7 脚本开关 | 在动作等待期间关掉服务端脚本，尝试普通动作和后台动作，再开启 | 不再进入脚本，等待的世界意图不落地；已动钱的请求返回 UNKNOWN；原生管理继续可用 |
| A8 许可管理 | 批准测试 App，分别开放所有人、指定离线 UUID、撤销某人、取消所有人档、清空许可 | 按 UUID 生效，所有人档下不能假装撤掉某一人；每次改动均先写审计 |
| A9 作者与版本 | 禁用完整作者公钥、恢复，再增加版本下限/吊销版本/摘要；切前端 optional/forced/off | 已开页面和后续请求重新检查；换作者不能继承旧作者身份；策略修改关联当前包版本的审计 |
| A10 经济只读 | 在内置货币和存在的外部钱包档分别打开对账 | 内置账显示余额、托管和供给差异；外部余额不能核对时明确显示，不能冒充平账 |
| A11 审计拒绝 | 将当日审计配额用满，或让审计目录不可写，再修改许可、批准、配额与预设 | 更改拒绝，不出现「更改成功但没有审计」；恢复存储后可重新预览 |

## 输入页面回归

在部署许可详情中，分别点击「玩家 UUID」标签、空值行及长 UUID 的最后一行，均应出现「输入中」及底部编辑提示。Ctrl+A/Ctrl+V 替换 UUID，左右箭头、Shift 选择、Home/End 移动光标；Enter 结束编辑后再预览授权。审批确认页同样分别点击理由标签与内容行，输入含 e 的中文/英文理由，手机不能被背包键关闭；Tab 转到新指纹，输入不应覆盖理由。关闭页面再进入不能保留旧焦点。

`NativeAdminInputTest` 直接调用真实页面的点击和键盘入口，覆盖空值、分行、焦点与编辑结果；原生渲染、系统剪贴板及输入法仍由游戏内测试核对。

## 崩溃与不明结果

只在可恢复的测试世界中执行，先保存一份基线。记录真实背包/钱包流水，再决定「已发生」或「未发生」，不能仅根据客户端是否收到成功提示判断。

| 编号 | 场景 | 核对结果 |
| --- | --- | --- |
| R1 外部退款已入账后异常 | 让测试钱包在入账后抛出异常，重启并等待多次超时扫描 | 同一托管不再次入账，原生页面列为待核对 |
| R2 钱包成功、世界账回滚 | 退款成功后恢复退款前的世界经济账快照，保留结算日志，再启动 | 日志与世界账不一致时进入 UNKNOWN，不能自动退款 |
| R3 确认已发生 | 核对 R1/R2 的钱包流水，在原生页面确认已发生，再重启 | 不再调用钱包；原账标为结清，确认记录仍防止复活退款 |
| R4 确认未发生 | 使用确定没有入账的故障，再原生确认未发生 | 可恢复一次结算机会，重新执行仍受归属、授权和连接检查 |
| R5 两本货币账 | 脚本创建托管后由定时退款进入不明结果，在原生页面核对 | 原生结算日志与脚本归属一起核对，无需分别放开两条重试入口 |
| R6 物品搬入和领取 | 在扣除/交付附近强制结束服务器，重启后查看收件箱与物品托管待核对 | 明确区分搬入和领取方向；确认已发生只推进或结束记录，不再次发物品 |
| R7 配置事务中断 | 在多配置写入中断，重启；再验证事务已提交后中断 | 未提交恢复整套旧配置；已提交恢复整套新配置，不混用新旧文件 |

运行每个任务时记录平台、客户端/服务器 JAR 的 SHA-256、步骤、实际结果、相关服务端日志和 UTC 审计文件。没有完成的游戏内任务标记「未测」，不要写成通过。

命令模板完整定义在固定文件中编辑，原生管理可查看模板、切换总开关并预览重载；名单保持只读。重载预览同时展示当前生效值与拟装载文件。换作者/降级已有独立原生页。上述界面、边界标签与真实模组行为继续按 `COMPLETION-TEST-TASKS.md` 验收；不能用配置断言替代实际按钮与游戏存档结果。
