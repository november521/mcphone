# P1 真服清单第 13 条：S15f 注册表生命周期 + S15g 脚本宿主接线 验证材料

状态：**未勾选**。Owner：S15f / S15g。最迟验证点：S17 合并后的第一个真服窗口，且在任何 P2 步骤开工之前。构建、单测或结构检查不得替代本项。

> `S15f` **只接线、不造货币**：面额表（id / 符号 / 小数位 / 用哪一档）属 `S15d′`。当前规则是"只给世界存档里已经出现过的货币按 `builtin` 档注册"，
> 所以"有一条能对平的账"这一条要等 `S15d′` 到货后才有得跑。本材料把步骤先摆好，真正的执行与勾选留到那时。

## 部署

1. 在隔离测试服备份世界、玩家数据与经济存档（`<世界>/data/mcphone_economy.dat` 与 `<世界>/mcphone/economy/` 下的 `economy.dat`、`economy.dat.stale`），
   记录模组版本、提交 SHA、加载器与 Java 版本。
2. 部署同一提交构建出的 NeoForge 1.21.1、Fabric 1.21.1、Forge 1.20.1 对应包；每个平台单独验证。
3. 先在一个**已知有账**的世界（或用 `S15d′` 配好一种货币并产生若干余额/托管）上验证，而不是全新世界 —— 全新世界按设计注册表为空。

## 触发与观察

1. 开服：确认日志里出现 `货币注册表：按 builtin 档注册了 N 种（…）`，且每种货币只有一条；`/mcphone economy audit` 能列出这些货币并逐条对平。
2. 停服再开服（同一 JVM，单人游戏连续开关世界）：确认新世界的注册表是新建的、旧世界的 provider 不复用、日志里两种货币集合按各自世界给出。
3. 制造一笔超时托管（把世界时间/存档里的 `createdAt` 拨早，或按 `S15h/S15i` 材料里的手法），确认运行中扫描把它**真的退回原主**，日志区分"退了"与"没找到 provider"。
4. 【S15g】客户端点一下脚本 App 的动作，记下请求 ID、回包码与服务端日志：**在 S17 之前应当稳定回 `NOT_DEPLOYED`** —— 脚本宿主已经装配（`ScriptRpcHandler` 不再是 null 管线），但部署表/授权表是 `DenyAll*` 占位，所以"本服没有这个 App 的已批准部署"是设计而非兜底。S17 合并后用同一份步骤复跑，确认请求**真的进到求值器**（回 `OK` 或稳定的业务错误码），且 `onDone` 恰好一次。

> ⚠ **这条端到端退款路没有自动断言覆盖**：生产里唯一会动钱的组合是
> `install → sweepNow → registry::get → GatedCurrencyProvider → 网关主线程快路径 → BuiltinProvider.refund`。
> 既有测试用的是假 provider 函数，新增的 `registryLifecycle()` 也只 mint 出账目、**一笔托管都没造**（它 `sweepNow()` 扫的是空集）。
> 所以它在合并时只有"源码推理"这一条凭证 —— **必须按上面第 3 步在真服上补验**，别在 `S15d′` / `S15g` 里当成已验。


4. 停机再启动，确认已结清的托管不再退第二次；`audit` 仍平。
5. `S15d′` 到货后补：两台配了不同货币 id 的服务器各跑一遍同一份 App 包，确认不改一行代码都能用（`#6`）。
