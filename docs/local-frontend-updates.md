# 本地纯前端 App 自动更新

基线：main `2c8565c`。本卡范围是本机 `mcphone/apps/`，不包含作者 feed、联网下载或服务端部署更新。

## main 原有行为与本次变化

原有代码在打开商店时扫描目录并替换变更包；并不需要重启游戏。但扫描/列元数据/启用混在同一条路径，替换没有 SDK 检查，也没有活动页面占用规则。脚本卸载后的重装转入 Java App 来源，漏过脚本检查。

本次保留原有读取、编译、签名和注册表接口，拆出两个职责：

- `LocalScriptUpdates`：客户端 tick 每两秒最多提交一轮后台读取/编译；结果在主线程启用，不积压任务。
- `LocalScriptCatalog`：维护已接受版本，检查注册表所有者，页面占用时延后，提交成功后才释放旧资源。

`LocalScriptSource` 负责签名/SDK 判据和商店交互。Java App 来源排除脚本，脚本首次安装和重装始终走同一套检查。

## 使用规则

1. 玩家仍需要在商店安装新 App；放进目录的新文件不会自动添加到主屏。
2. 已安装纯前端 App：把同 ID 的新版文件放到原路径，版本号必须递增；不需要打开商店。
3. 包里存在 `server.js` 或 `server/` 内容时，不进入本卡的定时纯前端更新。
4. 文件解析/页面编译/签名/SDK 有问题时，运行中的已接受版本保持不变。
5. 已签名 App 必须仍为相同可信作者。换作者、签名无效、摘除签名不能自动启用。
6. 已经接受的未签名本地 App 可更新为未签名递增版本；转为新签名作者必须人工确认。这保留本地导入选择，不产生服务器权限。
7. 手机界面正在打开时定时启用暂停，避免商店/详情页缓存的旧图标失效；该 App 在 HUD 中打开时也不切换。关闭手机界面及该 App 的 HUD 后，扫描启用新版，重新打开使用新的初始状态。
8. 同版本不同内容和低版本不会自动替换。版本按三段整数比较，避免 `1.10.0` 比 `1.9.0` 小的字符串比较问题。
9. 删除/坏包不会主动卸载内存中的旧版。这不是跨重启备份：磁盘上若只剩坏包，重启后无法从旧文件恢复，请自行保留旧文件。
10. 客户端扫描会读取文件完整摘要，包含签名元数据；同尺寸/同修改时间的文件变化也能检测。`.vue` 和 ZIP 都限定 256 KiB，读取本身也有界。

更新检测是轮询，不是文件系统监听；两秒是发起扫描的间隔，不是启用时延的硬保证。定时刷新要求连续两轮内容相同，通常约 2–4 秒后启用；大量包、慢磁盘或活动页面会延后。建议将完整新包写入临时文件后原子替换原文件，避免复制中间态。打开商店时仍保留同步扫描，可能等候一轮后台扫描完成。

## 自动化检查

- `LocalScriptFolderTest`：真实临时文件，同尺寸同时间换包、坏包重试、超大文件、删除重建。
- `LocalScriptUpdatesTest`：真实目录提交类，模拟注册表拒绝/冲突、活动页延后、重试、资源释放顺序；实际更新判据覆盖 SDK、身份、版本和前后端识别。
- 既有 `ScriptAppLoadTest`、`AppTexturesTest`：包编译与纹理回归。

## 待游戏验收（不能由构建结果代填）

快速样例：把 `docs/local-update-fixtures/v1.0.0/demo.vue` 放进游戏的 `mcphone/apps/demo.vue`，在商店确认未签名提示并安装。关闭手机及对应 HUD，再用 `v1.0.1/demo.vue` 替换同一路径，等待约 2–4 秒后打开，标题应显示新版。正式更新建议先写入临时文件，再替换原文件。

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| L01 | 安装纯前端 v1.0.0，关商店，把原文件换为标题不同的 v1.0.1，等待后打开 | 新标题；主屏排列不变；无须开商店或重连 |
| L02 | 保持 v1.0.1 页面打开（另测副手 HUD），换 v1.0.2 | 旧页面保持；关闭手机界面及该 App 的 HUD，等待后再打开变为新版；没有旧纹理误释放 |
| L03 | 替换为损坏文件，随后修好为 v1.0.3 | 坏包不顶掉旧版；修好后自动更新；没有每轮刷同一个坏包警告 |
| L04 | 替换为相同尺寸并保留修改时间的 v1.0.4 | 仍发现新版 |
| L05 | 尝试同版本不同内容、低版本、SDK 超出当前版本 | 保持旧版 |
| L06 | 已签名包换为其他作者、摘签名、坏签名 | 保持旧版；不会记为新作者已信任 |
| L07 | 卸载脚本，重新打开商店，再安装 | 仍在本机脚本来源；签名和 SDK 检查继续生效 |
| L08 | 放一个全新 App 文件但不点击安装 | 商店可发现，主屏不会自动增加 |
| L09 | 放带后端的包，关闭商店后替换 | 定时纯前端更新不处理它；服务端部署不受本卡改动影响 |
| L10 | 更新扫描期间退出世界，重新进入；手机和 HUD 同时使用同一 App | 仅在主线程启用；活动页全部关闭后才切换；没有崩溃 |

## 后续边界

没有在本卡中加入作者 feed、远程下载、版本见证持久化、自动回滚到磁盘旧包、安装列表实时重画或任意旧状态迁移。需要这些行为时应各自另开小卡，沿本地候选→校验→目录提交接口接入。
