## 部署

1. 在隔离测试服备份世界、玩家数据与经济存档，记录模组版本、提交 SHA、加载器和 Java 版本。
2. 部署同一提交构建出的 NeoForge 1.21.1、Fabric 1.21.1、Forge 1.20.1 对应包；每个平台单独验证。
3. 启用测试货币 provider、一个正常 App、一个带顶层可枚举 getter 炸弹的 App，以及记录交易次数的测试 provider。

## 触发与观察

1. 五个玩家并发提交畸形 `parse`、未知 cycle、store/shared 超配额、`setLong` 边界外输入；确认请求被拒、无部分写入、无玩家或 App 熔断。
2. 同 App 两个 worker 交错成功、预算中断和脚本未捕获错误；保存主线程日志中的完成顺序，确认每个完成均为“处分先落地，回调后发生”。
3. 连续制造三次应记过的脚本错误，确认只封禁目标 App/玩家；其他玩家与其他 App 保持可用，五分钟后恢复。
4. 运行 getter 炸弹，确认该请求仍完成一次；随后立即调用另一 App，确认 worker 仍服务、请求账本无 `RESERVED` 卡项。
5. 让 pay 成功返回后触发预算中断，并尝试第二次动钱；确认最终 `UNKNOWN`、provider 流水只动一次、无 strike。
6. 让 provider 分别抛 `ScriptAbort`、普通异常和 `Error`，文案包含 U+2028、U+2029、U+202E 与 `§`；确认不记过、动钱路径为 `UNKNOWN`，日志中控制字符已转义或替换。
7. 记录队列满与余额不可用路径，确认没有错误 strike，且客户端没有自动重试 `UNKNOWN`。

## 证据与恢复

- 附服务器日志、线程名、事件序列、每位玩家 strike 前后快照、provider 流水、请求完成计数以及三个平台的版本信息。
